# 输入法候选质量 Fuzzy 测试

## 目标

从词库随机取样 → 输入拼音 → 检查候选词是否与拼音正确对应，帮输入法「找茬」。
脚本化、可复现（同一 `--seed` 出同一组取样），作为候选质量的回归基准。

## 用法

```bash
cargo build --release -p cnt-dict-tools           # 改完代码必须先重新构建

S=.agents/skills/fuzzy-test/fuzzy_test.py
python3 $S selftest                # 判定器自检（不需要词库，秒回）
python3 $S sample                  # 主指标：100 词随机取样（默认 seed=42）
python3 $S sample --n 200 --seed 7 # 换样本量/随机种子
python3 $S mono                    # 单音节专项：精确高频字是否进前 10
python3 $S words li sihou zhuchen  # 看具体拼音的候选、分数、拼音键与判定
python3 $S sample --user ~/.local/share/cnt/user.dict   # 复现真实用户场景
```

`sample` 在有读音误配时返回退出码 1（误配是最高优先级 bug），可直接当门禁用。

**默认空用户库**：不污染真实用户数据，也排除调频/误学干扰，测的是纯词库质量。

## 判定依据来自解码器自己

`cnt-dict-tools decode --tsv` 输出每条候选**实际走的拼音键**
（`拼音<TAB>排名<TAB>候选<TAB>分数<TAB>拼音键<TAB>覆盖`，整句多段用 `-` 连接），
脚本据此分类，不需要复制模糊音规则表：

| 分类 | 判据 | 例 |
|---|---|---|
| **精确** | 键拼接 == 输入 | `xianzai` → 现在 `{xianzai}` |
| **模糊** | 折叠模糊写法后与输入等价 | `sihou` → 时候 `{shihou}` |
| **补全** | 输入是键的前缀（尾音节还没打完） | `zhongguor` → 中国人 `{zhongguoren}` |
| **部分** | 覆盖列是 `part:<前缀>`，且键与该前缀对得上 | `nihaoshijie` → 你好 `{nihao}` |
| **误配** | 以上都不是 —— **最高优先级 bug** | 输入 `zhongguoren` 出「和」 |

部分候选是增量确认的修复入口，判定时拿**它实际覆盖的那一段**比对（否则「你好」
对 `nihaoshijie` 会被误报成读音误配）。覆盖信息由解码器给出（TSV 第 6 列），
不靠脚本猜。

模糊折叠是启发式的（全串替换 + 韵母折到不动点，见 `canon()` 注释），
所以每次改它都要先跑 `selftest`——**别让判定器自己误报，把统计带偏**。
手写判定最容易犯的错就是把合法的模糊/补全候选记成误配。

## 判定基准

| 指标 | 目标 |
|---|---|
| 目标词 #1 命中 | ≥ 60%（常用词 #1 ≥ 80%） |
| 前 5 命中 | ≥ 85% |
| 前 10 命中 | ≥ 95% |
| 读音误配 | ≈ 0（出现即高优先级 bug） |
| 单音节专项（`mono`） | 词库高频前 10 字进候选前 10 ≥ 75% |

当前基线（空用户库，`--seed 42`）：

```
#1 命中 62 | 前5 91 | 前10 93 | 未出现 7
候选来源分布（前 10）：精确 73% 模糊 6% 补全 0% 部分 19% 误配 0%
单音节专项：词库高频前 10 字进候选前 10 = 86%
```

单音节专项曾长期停在 77%：`freq ≤ 100` 的读音一律给 `SECONDARY_BASE(-6.0)`，
而词库把「不在 LM unigram 的读音」全记成 `freq=1`，于是 Ext-B 字形（㙢/㝵/㮶）
拿恒定 -6.000 压过走 LM unigram 的 5000 频常用字（扪 -6.115、铄 -6.17），
把 men/de/shuo/fa/zai 的候选 4~10 位整段占掉。现在按「在不在 LM 词表」分流
（见 `reading_base`）。

「未出现」基本是 freq ≤ 5000 的生僻字（廼/髁/艡/㟜），属词库长尾，不必追。

## 工作流

1. 改动前跑一遍 `sample`（记下 seed）+ `mono`，存下数字；
2. 改代码 → `cargo build --release -p cnt-dict-tools`；
3. 用**同一 seed** 重跑，逐项对比；误配必须为 0，前 5 命中不得下降；
4. 失败样例用 `words <拼音>` 看分数与拼音键，定位是切分、打分还是排序问题；
5. 性能一并核对：`cnt-dict-tools bench data/cnt.dict data/lm.cntl 200`
   （候选质量不能拿延迟换，见 AGENTS.md 的可观测性约定）。

## 注意事项

- 严重度排序：**读音误配 > 常用词排名靠后 > 低频词未出现**
- 用户库隔离是默认行为，测真实用户场景才传 `--user`
- 需要 fastrace 阶段数据（定位慢样例）时：
  `cargo build --release --features "fastrace/enable" -p cnt-dict-tools`
- `data/` 不入库（见 AGENTS.md），缺文件时脚本会明确报出缺哪个

# 输入法候选质量 Fuzzy 测试

## 目标

从词库随机取样 → 输入拼音 → 检查候选词是否与拼音正确对应，帮输入法"找茬"。
每次跑 100 个词，输出命中率统计 + 问题样例，作为候选质量的回归基准。

## 被测对象

```bash
# 输入拼音，拿用户视角候选（与 daemon 完全同一条路径：整句 + 补全 + 词候选）
target/release/cnt-dict-tools decode data/cnt.dict data/lm.cntl <拼音>...
```

- **默认临时空用户库**：不污染真实用户数据，排除调频/误学干扰，测纯词库质量
- 复现用户场景：`--user ~/.local/share/cnt/user.dict`（含用户调频与误学词）
- 改动代码后先 `cargo build --release -p cnt-dict-tools` 再测

## 测试流程

1. **取样**：从 `data/wordlist.tsv`（`拼音\t词\t频率`，20 万+ 词）随机取 100 词
   - 覆盖各词长（1/2/3/4+ 字）与频率带；常用词（频率 > 10）至少占一半，
     避免全测生僻词
   - 记录每个取样词的 (拼音, 目标词, 频率)
2. **输入**：对每个取样词跑 `decode data/cnt.dict data/lm.cntl <拼音>`，
   取前 10 候选
3. **判定**，对每个取样词检查：
   - **目标词命中**：在候选中的排名（#1 / 前 5 / 前 10 / 未出现）
   - **候选读音**：用 `data/wordlist.tsv` 建立 词→拼音 反查表，逐一校验
     候选词读音与输入拼音的对应关系：
     - 完全匹配（目标词本身，或同音词）
     - 部分匹配（如输入 `diyige` 出「第一个」，读音是输入的前缀 + 后续）
     - **误配**：读音与输入完全无关（如输入 `zhongguoren` 出「和」）——最高优先级 bug
4. **统计**：汇总 #1 / 前5 / 前10 / 未出现 命中率、误配数

## 判定基准

| 指标 | 目标 |
|---|---|
| 目标词 #1 命中 | ≥ 60%（常用词 #1 ≥ 80%） |
| 前 5 命中 | ≥ 85% |
| 前 10 命中 | ≥ 95% |
| 读音误配 | ≈ 0（出现即高优先级 bug） |

未达标时，针对失败样例分析原因（切分错误 / 频率排序 / 用户调频干扰等），
修完重跑同一组取样词验证。

## 报告格式

```
fuzzy 结果（100 词，空用户库）：
  #1 命中 68 | 前5 87 | 前10 94 | 未出现 6
  误配 2：
    zhongguoren → 「和」读音 he 与输入无关 (#3)
    shijian     → 「湿巾」读音 shijin 部分误配 (#5)
  常用词前5未命中 3：
    sihou → 时候 排名 3（候选：是后 死后 时候 …）
```

## 注意事项

- 用户库隔离是默认行为，测真实用户场景才传 `--user`
- 误配 > 高频词排名靠后 > 低频词未出现（严重度排序）
- 若需 fastrace 阶段数据（定位慢的样例）：构建时
  `cargo build --release --features "fastrace/enable"` 全局开启 trace
